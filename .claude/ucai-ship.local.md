Create a comprehensive **Redundancy & Logical Contingency Framework** (The Never Forget System) designed to capture critical dependencies and Action/Reaction sequences during the construction of complex projects. This system serves as a cognitive safety net to ensure that specific components (A and B) are always integrated into the build process of a primary objective (C). # Rubberduck Reasoning The user is grappling with the forgotten dependency problem. They know that when building **C**, items **A** and **B** are essential, but the momentum of building often leads to oversight. They also observe a lack of conditional awareness in others—the if this, then that logic that defines robust systems. To solve this, I need to specify a system that does not just list tasks, but maps the **connective tissue** between them. * **Intent:** Moving from I might forget to The system will not let me proceed without. * **Constraints:** It needs to be practical enough to use daily but rigorous enough to catch edge cases. * **Interpretations:** A and B are not just parts; they are often safeguards, documentation, or secondary triggers that people ignore in favor of the main task. * **Resolution:** I will frame the specification around a **Trigger-Action-Validation** loop. # Assumptions * The user works on iterative projects where C is a repeatable or modular task. * A and B are often non-functional requirements (like security, logging, or notifications) or critical dependencies. * The user prefers a structured, logical flow over a simple to-do list. # Clarifying Questions * Are A and B static (the same for every project) or do they change based on the nature of C? * Is this system intended for personal use, or for managing a team that lacks this if/then foresight? # Specification ## 1. Minimal Viable Version **The Hard-Stop Checklist** * **Static Entry Gate:** Before work on **C** begins, **A** and **B** must be defined in a Required Assets field. * **The Binary Lock:** A simple checklist where the Submit/Complete action for **C** is physically or procedurally blocked until **A** and **B** are checked off. * **Logic Link:** One If/Then statement per project: If C is deployed, then B must be verified. ## 2. Standard Version **The Dependency Mapping Matrix** * **Action/Reaction Ledger:** A table-based format where every task in **C** is mapped to its reaction. * *Example:* [Task: Update Database] -> [Reaction: Update Documentation (A)] -> [Reaction: Notify Stakeholders (B)]. * **Pre-Flight & Post-Flight Protocols:** Standardized Station Checks at the 0% and 100% marks of a project specifically looking for **A** and **B**. * **The Shadow Task Method:** For every user-story or task created for **C**, the system automatically generates sub-tasks for **A** and **B**. ## 3. Advanced Version **The Logical Contingency Engine** * **Recursive Dependency Graph:** A visual mapping tool that shows how **C** is nested within **A** and **B**. If a node in **C** changes, the system highlights which parts of **A** and **B** are now stale or at risk. * **Conditionality Triggers:** Implementation of a formal Logic Gate system: * **State-Based Triggers:** While C is in state [Building], A must be in state [Drafted]. * **Automated Validation:** Scripted checks that scan the environment to ensure **A** and **B** exist before allowing **C** to transition to Live. * **The Observer Protocol:** A dedicated feedback loop that records every time an Action occurred without a Reaction, updating the template to prevent future drift. # Edge Cases & Failure Modes * **The Checklist Fatigue Failure:** If **A** and **B** are too tedious, the user might blind-check them without actually doing the work. * *Fix:* Require a Proof of Work (e.g., a link or a screenshot) for **A** and **B**. * **The Scope Creep Case:** **C** becomes so large that **A** and **B** are no longer sufficient. * *Fix:* Implement a Complexity Trigger that forces a re-evaluation of dependencies if the project exceeds a certain size. * **The Invisible Dependency:** A new factor, **D**, emerges that was not in the initial Never Forget list. # Success Criteria * **Zero Post-Live Corrections:** **C** is never finished only to realize **A** or **B** were missed. * **Cognitive Load Reduction:** The user no longer feels anxiety about forgetting, as the system handles the Action/Reaction monitoring. * **Scalability:** The framework can be applied to a 10-minute task or a 10-month project with the same logical integrity. # Optional Enhancements * **Visual Dashboard:** A Red/Green status light system for all dependencies. * **AI-Assisted Scanning:** Using a language model to read the description of **C** and suggest potential **A** and **B** requirements that the user might have missed. * **Retrospective Logging:** A log that tracks the Cost of Forgetting to provide data-driven motivation for maintaining the system.
